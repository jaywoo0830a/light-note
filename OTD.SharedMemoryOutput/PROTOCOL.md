# OTD ↔ light-note 공유 메모리 계약 (v1)

이 문서는 **양쪽 구현의 유일한 계약**이다. C# 플러그인(`SharedMemoryTap.cs`)이 쓰고,
Rust 앱(`src/otd/shm.rs`)이 읽는다. 한쪽만 바꾸면 조용히 깨지므로 **버전을 먼저 본다**.

## 왜 파이프(JSON-RPC)가 아니라 공유 메모리인가 — 실측 비교

| 경로 | 리포트당 비용 | 근거 |
|---|---|---|
| OTD RPC(`DeviceReport`) | **약 100~300 µs** | 매 리포트에 `TabletReference` 약 1 KB를 JSON으로 직렬화 + 파이프 쓰기. 이 PC에서 직접 받아 확인한 페이로드다 |
| 공유 메모리(이 계약) | **약 50~100 ns** | 고정 64 B 구조체 기록 + 인터락. 직렬화 없음, 시스템 호출 없음 |
| 읽는 쪽(Rust) | **리포트당 syscall 0회** | `MapViewOfFile`을 한 번 하고 나면 원자적 load만 한다 |

즉 400 리포트/초에서 RPC는 코어의 4~12%를 쓰고, 이 계약은 0.004%를 쓴다. **차이는 1000배 이상**이다.

## 이름과 크기

```
이름:  light-note.otd.shm      (.NET MemoryMappedFile.CreateOrOpen 로 만든다)
크기:  128 B 헤더 + 4096 × 64 B = 262272 B
```
.NET이 만든 이름은 **세션 네임스페이스**에 들어간다 → 읽는 쪽은 `Local\light-note.otd.shm`을
먼저 시도하고, 실패하면 이름 그대로 시도한다(둘 다 실패하면 "플러그인 없음"이다).

## 헤더 (128 B, 오프셋 0)

| 오프셋 | 형 | 필드 | 뜻 |
|---|---|---|---|
| 0x00 | u64 | `magic` | `0x4C4E_4F54_4453_4D31` (`LNOTDSM1`) — 다른 매핑과 구별 |
| 0x08 | u32 | `version` | 1 — **다르면 읽지 않는다** |
| 0x0C | u32 | `sample_size` | 64 |
| 0x10 | u32 | `capacity` | 4096 |
| 0x14 | u32 | `flags` | bit0 = 플러그인 살아 있음 |
| 0x18 | u64 | `write_seq` | 기록한 샘플 수(단조 증가) — 읽는 쪽의 유일한 커서 |
| 0x20 | u64 | `reserved2` | 0 |
| 0x28 | f32 | `max_x` | 태블릿 최대 X(장치 단위) |
| 0x2C | f32 | `max_y` | 태블릿 최대 Y |
| 0x30 | f32 | `max_pressure` | 최대 필압 |
| 0x34 | u32 | `reserved` | 0 |
| 0x38 | u64 | `heartbeat` | `Stopwatch.GetTimestamp()` — 플러그인이 살아 있는지 |
| 0x40 | u8[64] | `tablet_name` | UTF-8, NUL 종료(없으면 빈 문자열) |

`max_*`는 플러그인이 모르면 0으로 둔다 → 그때는 앱이 OTD RPC `GetTablets`로 채운다
(필터는 `IOutputMode.Tablet`에 접근할 수 없다 — 그래서 0이 정상일 수 있다).

## 샘플 (64 B, 오프셋 `128 + (seq % 4096) * 64`)

| 오프셋 | 형 | 필드 | 뜻 |
|---|---|---|---|
| 0x00 | u64 | `seq` | 슬롯 표식: `2*seq` = 완성, `2*seq+1` = 쓰는 중. **정확히 일치할 때만** 유효 |
| 0x08 | f32 | `x` | 태블릿 좌표(장치 단위, **변환 전**) |
| 0x0C | f32 | `y` | 〃 |
| 0x10 | f32 | `pressure` | 원시 필압(0 = 안 닿음) |
| 0x14 | f32 | `tilt_x` | 도(°). 보고하지 않으면 0 |
| 0x18 | f32 | `tilt_y` | 〃 |
| 0x1C | f32 | `rotation` | 도(°). 보고하지 않으면 0 |
| 0x20 | u32 | `flags` | bit0 접촉, bit1 지우개, bit2 범위이탈, bit3 근접, bit4~11 펜 버튼 |
| 0x24 | u32 | `hover_distance` | 근접 거리(장치 단위) |
| 0x28 | u64 | `t` | `Stopwatch.GetTimestamp()` (QPC, 100 ns 단위) |
| 0x30 | u8[16] | `reserved` | 0 |

## 쓰는 쪽 (C# 플러그인) — 규칙 셋

1. **블로킹 금지.** `Consume`은 디바이스 리더 스레드에서 동기 호출된다. 여기서 기다리면
   펜 입력 자체가 멈춘다. 쓰기만 하고 즉시 돌아온다.
2. **반드시 통과시킨다.** `Emit?.Invoke(report)`를 빠뜨리면 파이프라인이 끊겨 커서가 죽는다.
3. **표식 순서를 지킨다**:
   ```
   seq = Interlocked.Increment(ref write_seq)   // 이 샘플의 번호를 원자적으로 받는다
   slot = 128 + (seq % 4096) * 64
   slot.seq = seq * 2 + 1                        // 먼저 "쓰는 중"을 공개한다
   slot.x = ...; slot.pressure = ...; ...        // 필드를 기록한다
   slot.seq = seq * 2                            // 마지막에 "완성"으로 바꾼다
   ```
   표식이 필드보다 먼저/나중에 오는 순서가 **계약이다**. 표식을 `2*seq`/`2*seq+1`로 인코딩하는
   이유: 두 태블릿이 동시에 써도(번호가 홀/짝으로 갈리지 않아도) 슬롯마다 자기 번호와 비교할 수 있다.

## 읽는 쪽 (Rust 앱) — 규칙 셋

1. `magic`/`version`/`sample_size`가 다르면 **읽지 않는다**(낡은 플러그인 = 없는 것과 같다).
2. `last_seq`를 기억하고, `max(last_seq+1, latest-4095)..=latest`만 읽는다 — 밀려서 건너뛴 수는
   **앱이 세어서** 화면에 보여준다(그리는 앱에서 옛 좌표를 따라 그리면 더 나쁘다).
3. 슬롯의 표식이 **정확히 `2*seq`일 때만** 채택한다(그 사이에 덮여 썼으면 표식이 달라진다).

## 앱이 쓰는 것 / 쓰지 않는 것

쓰는 것: `pressure`(헤더의 `max_pressure`로 0~1 정규화), `tilt_x`/`tilt_y`/`rotation`(닙이 눕는 각도와
배럴 회전), `flags`의 bit0(접촉) · bit1(지우개) · bit4~11(펜 버튼 — 진단 패널과 로그에 표시).

쓰지 않는 것:

- `x`/`y` — 잉크가 놓이는 자리는 **캔버스의 포인터 이벤트**(화면에서 펜이 실제로 닿은 점)가 정한다.
  태블릿 좌표를 앱이 매핑하면 창 크기·줌·페이지 비율에 따라 커서와 잉크가 어긋난다.
- `hover_distance` — 근접 거리(장치 단위)는 근접 상태를 그리는 앱이 아니면 쓸 데가 없다.
- `AuxReport`(익스프레스 키)는 `flags`에 없다 — 필요해지면 v2에서 넣는다.
